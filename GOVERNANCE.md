# Governance

Nexum follows an incremental governance model.

## Early Stage

During the early stage, project maintainers are responsible for merging Pull Requests, managing releases, accepting or rejecting RFCs, maintaining the development plan and project policies, and appointing additional maintainers.

Technical decisions should leave a traceable record through public Issues, Discussions, RFCs, and Pull Requests whenever practical.

## Maintainers

Nexum maintainers are responsible for long-term project maintenance, code review, releases, and community collaboration. They should remain active in the project and follow the Code of Conduct.

Current maintainer:

- AllianceEcho - Project Maintainer

As the community grows, additional maintainers may be appointed with clearly defined responsibilities.

## Major Changes

Major changes involving public APIs, protocols, data formats, core architecture, or compatibility should be documented through an RFC or ADR.

## Changing Governance

Governance may be changed through a public Pull Request with an explanation of the reason for the change.
